# Brief it: guide

Give your agent the goal and the details it would otherwise guess, in the first request of a real piece of work.

> **Detection is not available yet.** Dram cannot recognize this pattern in your sessions today, so finishing this guide will not show a recognition. The guide is still worth doing: a good brief saves a correction on this task.

## 1. Pick a real task you are about to start

Choose the next feature, fix or change you were going to ask your agent for in your own project.

- If you have no piece of work to start right now, **stop here**. There is no exercise to do and nothing to recognize; come back when you have a real task.

## 2. Answer two questions for yourself

- **What does done look like?** One line: the behaviour you will check.
- **What must not change, or what should it reuse?** One line: an existing service, an API, a behaviour such as timezone handling, a limit.

Only include context the work will actually use. Long background the agent will not need is not a better brief.

## 3. Take the step: send the brief

Write your real request with the goal and both lines, for example:

> Add password reset. Use the existing email service, and links expire after an hour.

Write it yourself. If you ask the agent to draft a brief, read and correct it before saying go; "ok" on a draft you did not read is not your brief.

**Done:** you sent a request with the goal and at least one constraint or fact the work needed, and the agent worked without having to ask or guess about it. That brief is what this pattern recognizes once detection is available.

**Not done yet:** if you answered the questions above but sent the request without them, or only sent the goal, the pattern has not happened yet. That is fine. Nothing is recorded against you; try it on your next task.

## Later

Once several patterns happen on their own, a saved command or issue template that asks for the goal and the constraints can prompt you every time. That comes later, and it only counts when you actually use it.
